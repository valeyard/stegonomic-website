ESP32 wireless doorbell

A self-built wireless doorbell system on ESP32 microcontrollers, with a local MQTT backend and a live monitoring dashboard in the browser.

I wanted a doorbell I fully understood and controlled: no cloud account, no subscription, nothing leaving my home network. The system is two ESP32 units talking through a local message broker. One is mounted on the wall next to my flat's intercom system; it receives the ring and relays it to the second unit in the living room, which has the flashing light.

The hardest part was making the messaging between the two ESP32s reliable. At first, the little ESP32-C3 mini boards I was using didn't have a strong enough signal to make it through the walls; upgrading to ESP32-S3-WROOM boards fixed that.

My first version used ESP-NOW, Espressif's direct device-to-device protocol. It worked, but reliability was inconsistent, and an ESP-IDF v5.5 update changed the callback API underneath me. Rather than patch around it, I moved the system onto MQTT with a Mosquitto broker running in Docker. That gave me proper delivery, visibility into every message, and a clean way to add more devices later.

Along the way I worked through:

  • Docker networking quirks on Windows
  • message delays caused by client-side buffering
  • clients knocking each other offline through duplicate IDs
  • moving the firmware between ESP32-C3 and ESP32-S3-WROOM boards

To see what was happening, I built a monitoring dashboard as a single HTML file with no build step and no server code. It connects to the broker over WebSockets and shows presses and device status live.

It's been installed and running at home since February 2026.

Built with

ESP32-C3 / ESP32-S3-WROOM · Arduino / ESP-IDF · MQTT (Mosquitto in Docker) · WebSockets · HTML/JS · 3D-printed enclosures
